# KIBO 제출자료 ⑤ 기술보증기금 심사 대응 Q&A

> 담당자 질의에 대비한 답변 초안입니다. 굵게 표시한 부분은 계약서·코드에서 직접 확인된 사실이고,
> [검토 필요]로 표시한 부분은 신청자(우리동네소프트)가 본인의 사업계획에 맞게 직접 채워야 하는 부분입니다.

---

### Q1. 매출이 아직 없는 이유는?

특성화고신문 웹사이트 개발·유지보수·운영 계약(전자계약, 체결 기재일 2026-09-23)은 **최근에 체결된 계약**이며, 계약 구조 자체가 고정 도급비가 아니라 **웹사이트에서 실제로 발생하는 총수익의 40%를 배분받는 수익배분형 모델**입니다. 매출은 웹사이트 운영을 통한 광고·제휴·후원·유료 콘텐츠 등에서 발생하는데, 서비스가 최근 개발·오픈 단계에 있어 아직 유의미한 누적 매출로 이어지지 않았습니다. [검토 필요: 실제 서비스 오픈일, 현재 트래픽/이용자 규모 등 구체적 단계를 신청자가 기재]

### Q2. 실제 계약이 있는가?

예. 특성화고신문(발주사, 사업자등록번호 214-13-75982, 대표 강승구)과 우리동네소프트(수행사, 사업자등록번호 483-08-03760, 대표 송지훈) 간 전자계약 형태의 「웹사이트 개발·유지보수·운영 용역계약서」가 존재합니다. 다만 제출용 PDF 원본의 서명란은 공란으로 되어 있어, **전자서명 완료를 증빙하는 별도 자료(체결확인서 등)를 함께 제출**해야 완전한 증빙이 됩니다 ([KIBO_CONTRACT_06_EVIDENCE_CHECKLIST.md](KIBO_CONTRACT_06_EVIDENCE_CHECKLIST.md) 참조).

### Q3. 계약 내용은 무엇인가?

발주사가 운영하는 웹사이트 및 관련 시스템의 ①신규 개발, ②관리자 페이지 및 기능 개선, ③외부 API 및 서비스 연동, ④오류 수정 및 기술 지원, ⑤웹사이트 운영 지원을 수행사가 담당하고, 그 대가로 웹사이트에서 발생하는 총수익을 발주사 60% : 수행사 40%로 배분받는 계약입니다(제1·3·6조, 별첨1).

### Q4. 계약금액은 얼마인가?

**고정 계약금액이 아니라, 웹사이트 총수익의 40%를 수익배분받는 구조**입니다. 계약서 어디에도 정액의 용역대금 조항은 없으며, 이는 계약서 제6조에 명시된 사실입니다. 실제 배분·지급된 금액이 있다면 이는 계약금액이 아니라 "실적 수익배분금"으로 별도 증빙자료를 통해 확인해야 합니다.

### Q5. 우리동네소프트가 실제 수행하는 업무는?

계약서 제3조·별첨1 기준: 웹사이트 신규 개발, 관리자 페이지 및 기능 개선, 외부 API 및 서비스 연동, 오류 수정 및 기술 지원, 웹사이트 운영 지원. 실제로 `hs-portal` 코드베이스에서 이 업무들이 모두 해당 기능으로 구현되어 있음이 확인됩니다([KIBO_CONTRACT_02_TECH_MAPPING.md](KIBO_CONTRACT_02_TECH_MAPPING.md)).

### Q6. 실제 개발한 기술은 무엇인가?

- 백엔드: FastAPI(Python) + SQLAlchemy, JWT 인증(`auth.py`), 토스페이먼츠 결제 연동(`toss.py`)
- 프런트엔드: React(Vite), Leaflet 지도, recharts 통계 시각화
- 외부 연동: NEIS(나이스) 교육정보 개방 포털 API(`import_neis.py`), 카카오 지오코딩 API(`geo.py`), Anthropic Claude API 기반 진로상담 챗봇(`career_chat.py`), 특성화고신문 기사 자동 크롤링(`articles.py`)
- 인프라: 네이버클라우드 서버 배포, systemd 서비스화, nginx + Let's Encrypt HTTPS, 자체 서버 모니터링 위젯

### Q7. 계약과 현재 개발된 소프트웨어는 어떻게 연결되는가?

계약서상 발주사의 사업자등록번호(214-13-75982), 대표자명(강승구), 이메일(news@sinmoon.net)이 실제 운영 코드(`backend/app/main.py`)에 하드코딩되어 있어, **계약서의 발주사와 실제 서비스 코드가 동일한 대상임이 코드 수준에서 확인**됩니다. 계약상 업무 항목과 코드 구현 내역의 1:1 대응 관계는 [KIBO_CONTRACT_02_TECH_MAPPING.md](KIBO_CONTRACT_02_TECH_MAPPING.md)의 표를 참조하십시오.

### Q8. 계약 종료 후에도 기술을 활용할 수 있는가?

예. 계약서 제13조(지식재산권 및 결과물) 2항은 "수행사가 계약 체결 이전부터 보유하거나 별도로 개발한 기술, 라이브러리, 프레임워크, 공통 모듈, 개발도구 및 일반적인 노하우는 수행사에 귀속한다"고 명시하고 있습니다. 즉, 이번 프로젝트를 위해 만든 **범용 기술 자산(검색 엔진 로직, 인증 모듈, 결제 연동, 진로적성 매칭 알고리즘, 서버 모니터링 도구 등)은 우리동네소프트가 계속 보유·재활용**할 수 있습니다. 다만 "새로 작성된 프로젝트 전용 결과물"의 IP는 별도 합의가 없는 한 발주사가 대금을 모두 지급한 이후 합의된 범위에 따라 정해지므로(제13조 1항), **프로젝트 전용 산출물과 범용 기술 자산을 구분**해서 설명해야 합니다.

### Q9. 자금이 왜 필요한가?

[검토 필요 — 신청자가 채워야 할 항목] 현재 프로젝트에서 확인되는 실질적 필요는 다음과 같은 항목들입니다. 실제 자금 사용 계획은 신청자가 구체적 금액과 함께 작성해야 합니다.
- 서버·인프라 비용: 네이버클라우드 서버 운영, PostgreSQL 전환, HTTPS 인증서 갱신 등 지속적 인프라 유지비
- 외부 API 사용료: 카카오 지오코딩, Anthropic Claude API(진로상담 챗봇), 토스페이먼츠 수수료 등 사용량에 비례하는 비용
- 인력: 백엔드/프런트엔드 지속 개발, 콘텐츠·운영 지원 인력
- 추가 기능 개발: 진학정보 분석 고도화, 콜센터/전화상담 시스템 확장 등 코드베이스에 이미 착수된 기능의 완성도 제고

### Q10. 향후 어떻게 매출을 확대할 것인가?

두 층위를 구분해서 설명합니다.
1. **본 계약(특성화고신문 웹사이트)에 근거한 매출 확대**: 유료 노출 플랜(베이직/프리미엄/플래티넘) 가입 학교 확대, 광고·제휴 수익 확대, 유료 콘텐츠(진학정보 분석 등) 확대를 통해 웹사이트 총수익을 늘리고, 그 40%를 수익배분받는 구조를 통해 매출을 키웁니다.
2. **우리동네소프트의 자체 사업계획**: 본 계약과 별개로 우리동네소프트가 보유·개발 중인 다른 서비스(예: 사내에서 별도로 진행 중인 프로젝트들)가 있다면, 이는 **본 계약과는 무관한 별도 사업**이므로 혼동 없이 구분해 기재해야 합니다. [검토 필요 — 신청자가 해당 서비스명과 사업계획을 직접 작성. 본 문서는 "특성화고신문 웹사이트 계약" 하나에 근거한 사실관계만 다룹니다.]
