# UDJ 학교·교사 관련 실제 기능 (영상 제작용 분석)

- 분석일: 2026-10-02
- 대상: `frontend/src`(React), `backend/app`(FastAPI), 운영 사이트 https://udjschool.ggm.kr/ 공개 화면, 로컬 시연 환경(`video/school-demo`)
- 원칙: 코드와 실제 화면으로 확인한 기능만 적는다. 없는 기능은 "없음"으로 적는다.

## 0. 중요한 전제 — 선생님(teacher) 역할

- **결정(사용자, 2026-10-02): UDJ에서는 선생님 권한을 없애기로 했다.** 선생님 계정 검색·권한 부여·해제는 2026-09에 **기록해**(diary.ggm.kr)로 옮겨졌다(`backend/app/main.py` 의 "선생님 계정 (학교가 발급)" 주석, `partner.py`).
- 2026-10-02 영상 제작 시점에는 아래가 UDJ 코드·운영 번들에 남아 있었다 → **같은 날 코드에서 정리함(맨 아래 표)**. 운영 반영은 배포 후.
  - `Role.teacher`, `/teacher` 화면(학급 학생·재학생 인증·내 계정), `/api/teacher/*` 10여 개
  - 노출 플랜 탭 "기본 제공 기능" 목록의 **"선생님 계정 발급"** 문구(`BASE_FEATURES`)
  - 취업/진학 공개 설정의 "우리 학교 학생만" 선택지와 안내 문구("우리 학교 선생님과 학교 계정은 볼 수 있습니다")
- 따라서 **이번 영상은 '학교 계정' 중심**으로 만들었다. "교사 기능" 영상은 **학교 계정을 맡은 담당 선생님의 업무 가이드**(학교 계정으로 로그인해 하는 일)로 만들었고, `/teacher` 화면·학급·재학생 인증은 다루지 않았다.

## 1. 학교 활용 구조

```
[학교] ── 학교 계정 1개 (role=school, users.school_id → schools.id)
            │  신청: /school-account-request → 운영진 확인 전화 → 관리자 승인 → 임시 비밀번호 메일
            │  첫 로그인 시 비밀번호 변경 안내(must_change_password)
            ▼
       학교 관리 화면 /my-school  (통계 · 학교 정보 · 문의 관리 · 학교일정등록 · 취업/진학 정보 · 노출 플랜)
            │
            ▼  학교가 입력한 정보가 공개 화면으로 나간다
[학생·학부모] 검색 결과 · 학교 페이지 /schools/{id} · 학교 일정 /events · 취업/진학 공개 페이지 · 즐겨찾기 D-day
            │  문의(이메일로 답변 받음), 조회·즐겨찾기(학교 통계에 집계)
            ▼
       학교 관리 화면 (문의 관리 · 통계)
```

- 학교 계정은 **학교 하나에 연결된 대표 계정**이다(`User.school_id`). 학교별 사용자(여러 직원 계정) 기능은 없다.
- 학교 계정은 학생 개인 정보를 관리하는 화면이 없다. 학생과의 접점은 **문의(문의자가 직접 남긴 이메일·연락처)** 와 **집계 통계(조회수·즐겨찾기 수)** 뿐이다.
