# 학교생활 일지 · 수업 일지 기능 가이드

학생이 일지를 쓰면 AI가 **자기소개서 초안**으로 바꿔주고, 선생님께는 **생활기록부용 요약**을 보내주는 기능입니다.

## 흐름

```
선생님   : 사이트에서 일반 회원가입 (본인이 비밀번호 지정)
학교 계정: [선생님 계정] 탭 → 그 계정 검색 → 선생님 권한 부여 + 담당 학급 지정
선생님   : 로그인 → 학생 검색(아이디/이름/연락처) → 학급에 등록
학생     : 일지 작성 → [선생님께 제출]   ※ 학생은 글만 씁니다
선생님   : [제출된 일지] → AI 생기부 초안 + 항목별 요약
                        → 요약 클릭 → 학생이 쓴 원문 펼쳐보기
           [후기 관리] → 자동 보류된 악성 후기 → 보류 해제 / 삭제
```

- 학생 화면: 상단 메뉴 **학교생활 일지** (`/journal`) — 작성·제출만
- 선생님 화면: 상단 메뉴 **선생님** (`/teacher`) — AI 요약·학급 관리·후기 관리
- 학교 화면: **학교 관리 → 선생님 계정** 탭

## 계정 체계

| 역할 | 만드는 사람 | 할 수 있는 일 |
|---|---|---|
| 학생 | 본인 가입 | 일지 작성·제출, (등록된 경우) 학교 후기 작성 |
| 선생님 | 본인 가입 + **학교가 권한 부여** | 학급 학생 등록, 일지 AI 요약 열람, 후기 보류 관리 |
| 학교 | 관리자가 발급 | 학교 정보·문의·플랜, 선생님 계정 발급 |

선생님은 **직접 회원가입**하므로 학교가 남의 비밀번호를 정하거나 관리하지 않습니다.
학교는 가입된 계정을 이메일·이름·연락처로 찾아 **권한만 부여**하고, 담당 학급을 지정합니다.
권한 해제 시 계정은 삭제되지 않고 일반 사용자로 돌아갑니다.

## 후기 권한과 자동 보류

- **선생님이 학급에 등록한 학생만** 그 학교에 후기를 쓸 수 있습니다(미등록 시 403).
- 등록 해제하면 후기 작성 권한도 사라집니다.
- 아래에 해당하면 **자동 보류**되어 공개되지 않고, 선생님이 확인 후 해제/삭제합니다.
  욕설·비방 / 문자 도배 / 낮은 평점 + 너무 짧은 내용 / 특정 교사 지목 + 부정 표현 / 연락처·외부 링크
- 완곡한 비판("기숙사 시설이 아쉽고 급식도 그저 그래요")은 보류되지 않도록 조정돼 있습니다.

## 양식 (업로드해주신 서식 그대로)

**수업 일지**: 학습 목적 / 학습 목표 / 수업 내용 / 느낀 점 / 어려웠던 부분 / 해결 방법 / 결과 및 느낀 점
**학교생활 일지**: 가장 기억에 남는 것 / 기억에 남는 이유 / 얻은 교훈 / 실천·적용할 부분

**자소서 항목 9종**(양식의 1~9번과 동일): 성장과정, 성격의 장/단점, 학교생활, 강점 강화·약점 관리,
직무 역량과 문제 해결, 팀 활동 책임 수행, 도전과 목표 성취, 규정·원칙 준수, 조직을 위한 희생

## AI 엔진 — 기본은 '추출 요약', KoBART는 선택

서버 메모리를 고려해 **2단계 폴백** 구조로 만들었습니다.

| 모드 | 설치 필요 | 메모리 | 품질 |
|---|---|---|---|
| `extractive` (기본) | 없음 | 거의 없음 | 핵심 문장을 골라내는 방식 |
| `kobart` (선택) | torch + transformers | 워커당 약 1.5~2GB | 문장을 새로 생성하는 요약 |

**아무 설정 없이 배포하면 추출 요약으로 바로 동작합니다.** 인용문 기능은 두 모드 모두 원문을 그대로 뽑으므로 동일합니다.

### KoBART 켜기 (원할 때만)

```bash
# 1) 패키지 설치 (CPU 버전, 용량 약 2.5GB)
cd ~/hs-portal/backend
source .venv/bin/activate           # 가상환경을 쓰는 경우
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install transformers

# 2) .env 설정
echo "AI_SUMMARIZER=kobart" >> .env

# 3) 워커를 1개로 줄이기 (중요! 워커마다 모델이 올라가 메모리 초과 위험)
sudo nano /etc/systemd/system/udt-backend.service
#   ExecStart 의 -w 3  →  -w 1  로 변경
sudo systemctl daemon-reload
sudo systemctl restart udt-backend
```

> 최초 요청 시 모델을 내려받느라 수십 초 걸릴 수 있습니다(약 500MB).
> 메모리가 2GB 이하인 서버라면 켜지 마시고 기본(extractive)으로 두세요.
> 모델 로딩에 실패해도 자동으로 추출 요약으로 넘어가므로 서비스는 죽지 않습니다.

현재 어떤 엔진이 쓰이는지는 `GET /api/journal-meta` 응답의 `ai_backend` 값으로 확인할 수 있습니다.

## 필요한 .env 설정

```
SITE_BASE_URL=https://udjschool.ggm.kr   # 선생님께 보내는 메일 링크에 사용
SMTP_HOST / SMTP_USER / SMTP_PASSWORD    # 이미 설정돼 있으면 그대로 사용(비번찾기와 동일)
```

메일 발송은 **시스템 SMTP**(비밀번호 재설정에 쓰는 계정)를 사용합니다. 설정이 안 돼 있으면
"보내기"가 실패하고 안내 문구가 뜹니다.

## 개인정보 관련 참고

- 일지 본문은 학생 본인과, 링크를 받은 선생님만 볼 수 있습니다.
- 공유 링크는 추측하기 어려운 무작위 토큰(24바이트)입니다.
- `robots.txt`에서 `/journal`, `/journal-share/` 를 검색 수집 차단했습니다.
- AI 요약은 **초안**이며, 생기부 기재 전 교사 확인이 필요하다는 문구를 메일·화면에 넣었습니다.
