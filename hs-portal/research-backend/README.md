# 연구·논문 서비스

기록해(diary)에서 **연구·논문 기능만 떼어 낸** 별도 서비스다. 나중에 독립된
홈페이지로 세우려고 미리 갈라 두었다.

## 어디에도 기대지 않는다

| | UDJ | 기록해 | 여기 |
|---|---|---|---|
| 계정 | 자체 | UDJ 를 빌림 | **자체** (여기서 가입·로그인) |
| DB | 자체 | 자체(diary) | **자체**(research) |
| 포트 | 8000 | 8100 | **8200** |
| 화면 | 5173 | 5174 | **5176** |

기록해에 로그인돼 있어도 여기서는 **다시 가입해야 한다.** 계정을 잇지 않은
것은 그렇게 하기로 정했기 때문이다(완전히 따로).

## 띄우기

```bash
# 환경변수
export SECRET_KEY="충분히 긴 무작위 문자열"
export RESEARCH_DATABASE_URL="postgresql://..."   # 비우면 research.db(SQLite)
export OPENAI_API_KEY="..."                        # AI 연구 코치를 쓸 때만

python -m uvicorn app.main:app --port 8200 --app-dir research-backend
```

`RESEARCH_DATABASE_URL` 을 쓰는 이유: `DATABASE_URL` 을 그대로 쓰면 같은
서버에서 기록해와 나란히 띄울 때 서로의 DB 를 가리킨다.

## 검사

```bash
python tests/smoke.py
```

떼어낸 직후라 "연구가 잘 되는가"보다 **남의 것에 기대지 않는가**를 본다 —
여기서 가입·로그인이 되는지, 연구를 만들고 읽는지, 남의 연구를 못 보는지,
그리고 기록해에만 있던 화면(일지·자소서·이용권)이 정말 안 따라왔는지.

## 아직 없는 것

- **이용권·결제.** 기록해에서는 학교가 좌석을 사야 연구를 쓸 수 있었다.
  여기는 로그인만 하면 된다. 붙일 자리는 `main.py` 의
  `_require_product_seat` 한 곳이다 — 거기만 채우면 연구 엔드포인트 전부에
  걸린다.
- **비밀번호 찾기.** 메일 발송은 붙어 있으므로(`mailer.py`) 재설정 흐름만
  얹으면 된다.
- **모델 정리.** 일지·자소서 표가 아직 `models.py` 에 남아 있다. 쓰지 않으니
  해는 없지만, 새 DB 에 빈 표가 만들어진다. 화면이 자리잡은 뒤 지우는 편이
  안전하다 — 지금 지우면 무엇이 딸려 있는지 확인할 길이 줄어든다.
